Microsoft Entra ID: User Account Lifecycle

Created Microsoft Entra ID users, modified profile attributes, reset a credential, confirmed session revocation, and completed the soft-delete workflow for a test account — documenting the account lifecycle from provisioning through recovery and removal.

// OBJECTIVE

Why this project

User administration is a lifecycle, not a one-time provisioning task. This lab follows test identities through creation, profile maintenance, password recovery, session revocation, and deletion. Each screenshot is ordered exactly as the task was performed so the evidence lines up directly with the action being described.

// REVOKE

Revoke access to a Microsoft Entra ID user account

15

Select Revoke sessions

While still in RP One's profile, selected Revoke sessions from the toolbar to begin invalidating Microsoft Entra-managed session state for the account.

✓ REVOCATION CONFIRMED
16

Confirm session revocation

The Portal displayed the Do you want to revoke all sessions for the user? prompt. Selected Yes to confirm the action.

TECHNICAL NOTE

Revoke sessions invalidates Microsoft Entra refresh/session state under Entra's control. Existing access tokens and application-issued session cookies can have their own lifetimes, so this should not be described as an instantaneous guarantee that every application session disappears at once.

Result: session revocation was explicitly confirmed for RP One, requiring fresh authentication as Entra-managed tokens and sessions are reevaluated.

Verify restore and permanent-delete options

Confirmed RP Three appeared in Deleted users. With the account selected, the Portal exposed both Restore users and Delete permanently. Microsoft Entra retains a deleted user in a recoverable state for 30 days before permanent deletion begins automatically.

RECOVERY WINDOW

A soft-deleted user can be restored during the 30-day recovery window. If the account is permanently deleted, it cannot be restored and would need to be recreated.

Result: RP Three was removed from the active directory view, verified in Deleted users, and shown to have both recovery and permanent-deletion options during the 30-day retention window.

// TAKEAWAYS

What this demonstrates

  • User administration spans provisioning, profile maintenance, credential recovery, session management, and account removal — not just initial account creation.
  • Profile properties such as first name, last name, job title, and department are independent directory attributes that can support downstream identity workflows.
  • Password reset and session revocation solve different problems: one changes a credential, while the other invalidates Microsoft Entra-managed refresh/session state and forces reauthentication as tokens are reevaluated.
  • Deleting a user is normally a soft-delete operation first. The account remains recoverable for 30 days, during which an administrator can restore it or permanently delete it.
⚠ SANDBOX ENVIRONMENT — NOT PRODUCTION

This project was performed in a controlled training tenant. Production identity operations would also follow organizational approval, logging, least-privilege administration, access-control, and incident-response procedures.
