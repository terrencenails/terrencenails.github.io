Microsoft Entra ID: User Account Lifecycle

Created and modified Microsoft Entra ID user accounts, reset a user credential, and reviewed the session-revocation workflow through the Azure Portal — covering common identity administration tasks across the account lifecycle.

// OBJECTIVE

Why this project

User administration is a lifecycle, not a one-time provisioning task. This lab follows test accounts through creation, profile updates, password reset, and the session-revocation workflow. Each stage is documented in the same order it was performed so the screenshot directly supports the step being described.

// CREATE

Create Microsoft Entra ID user accounts

01

Open Microsoft Entra ID

Used the Azure Portal search bar to find Microsoft Entra ID and opened the service.

02

Start creating a new user

From the Microsoft Entra ID Overview page, opened + Add, selected User, and then selected Create new user.

03

Create RP One

Entered rp.one as the user principal name and RP One as the display name. The password remained set to auto-generate, and Review + create was selected to continue.

04

Create RP Two

Repeated the same user-creation process for rp.two with the display name RP Two.

05

Create RP Three

Created the third test account using rp.three with the display name RP Three.

06

Open the Users view

Returned to the tenant Overview and opened the Users view to verify the accounts that were created.

✓ VERIFIED
07

Verify all three users

Confirmed that RP One, RP Two, and RP Three appeared in the Users list. A manual refresh may be required before newly created directory objects appear in the Portal view.

Result: three test Member accounts were created and verified in Microsoft Entra ID before moving on to account modification.

// MODIFY

Modify a Microsoft Entra ID user account

08

Open RP One and select Edit properties

Selected RP One from the Users list, reviewed the account Overview page, and selected Edit properties from the toolbar.

09

Update identity fields

On the Identity tab, set First name to RP and Last name to One. These are separate directory attributes from the display name.

10

Update job information and save

On the Job Information tab, set Job title to Helpdesk Technician and Department to IT Helpdesk, then selected Save.

IN PRODUCTION

Identity attributes are commonly sourced from an authoritative HR or identity system rather than maintained manually. Attributes such as department and job title can also support dynamic group membership and other downstream identity workflows.

11

Open Reset password

Returned to the account Overview page and selected Reset password from the toolbar.

12

Confirm the password reset

The reset pane identified rp.one@radlabs3p.onmicrosoft.com and stated that the account would receive a temporary password that must be changed at the next sign-in. Selected Reset password to continue.

✓ RESET COMPLETE
13

Record the temporary password

The reset completed successfully and the Portal displayed the temporary password. The password was redacted in the screenshot and would need to be provided to the intended user through an appropriate verified channel.

IN PRODUCTION

Where self-service password reset is enabled and users are appropriately registered, many routine password resets can be completed without an administrator handling a temporary credential.

Result: RP One's profile attributes were updated and the account received a temporary password that must be changed at next sign-in.

// REVOKE

Revoke access to a Microsoft Entra ID user account

14

Locate Revoke sessions

While still in RP One's profile, located Revoke sessions in the toolbar. This is the control used to begin revoking the user's Microsoft Entra-managed session state when fresh authentication is required.

TECHNICAL NOTE

This screenshot documents the session-revocation control, not the confirmation dialog. The write-up therefore does not claim that every active application session was immediately terminated.

15

Review the final RP One account view

Finished the workflow on RP One's Overview page, where the account remains available for continued identity administration. This final screenshot records the account state at the end of the documented lab.

Result: the documented workflow covered user creation, profile modification, password reset, and the session-revocation control without claiming a revocation result that is not shown in the screenshots.

// TAKEAWAYS

What this demonstrates

  • User administration spans creation, profile maintenance, credential recovery, and session-management actions — not just initial account creation.
  • Profile properties such as first name, last name, job title, and department are separate directory attributes that can support downstream identity workflows.
  • Password reset and session revocation address different aspects of account recovery. This lab demonstrates the reset and identifies the revocation control while keeping the evidence aligned with what the screenshots actually show.
⚠ SANDBOX ENVIRONMENT — NOT PRODUCTION

This project was performed in a controlled training tenant. Production identity operations would also follow organizational approval, logging, access-control, and incident-response procedures.
