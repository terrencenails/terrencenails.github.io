Site-to-Site GRE Tunnel with Static Routing

Built a GRE tunnel between Router1 and Router3 across a routed simulated WAN, then added static routes so traffic could reach the remote LAN through the tunnel — testing connectivity after each stage instead of assuming the configuration was correct.

// OBJECTIVE

Why this project

A GRE tunnel creates a logical point-to-point path between two routers across an existing routed transit network. The tunnel provides the overlay, while routing determines which LAN traffic actually uses it. This project deliberately tests connectivity before the tunnel exists, after the tunnel interface is created but not bound, after it's bound to real endpoints, and after static routing is added — so each failure can be traced to the exact piece that was still missing.

Router1 and Router3 sit at opposite ends of a routed WAN, with Router2 acting as the transit device between them. The WAN underlay already provides reachability between the GRE source and destination addresses. GRE then builds a logical point-to-point overlay between Router1 and Router3, and static routes are added so each edge router knows to send remote-LAN traffic through that tunnel.

Result: routed reachability through the GRE overlay only came together once three separate things were true — the tunnel interfaces existed, they were bound to reachable WAN endpoints, and static routes pointed remote-LAN traffic into the tunnel. Testing after each stage made it possible to isolate exactly which dependency was still missing instead of debugging everything at once.

// TAKEAWAYS

What this demonstrates

  • An interface showing "up" doesn't by itself prove the intended traffic can reach its destination — a GRE overlay needs working underlay reachability plus routing that points the desired traffic into the tunnel.
  • Testing incrementally, after every single command, catches exactly where a chain of dependent configuration breaks — rather than configuring everything at once and debugging a wall of failures at the end.
  • GRE tunnels encapsulate traffic, but they don't encrypt it. This design connects two private address spaces over a transit network, but it isn't a substitute for IPsec if confidentiality of the traffic itself matters.
  • Static routes work cleanly here because the topology is small and fixed. In a larger or growing environment, this same tunnel would typically carry a dynamic routing protocol instead of hand-maintained routes on each side.
